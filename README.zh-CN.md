# codex-session-renamer

[English](README.md) | [中文](README.zh-CN.md)

手动修复近期 Codex 根会话标题，统一生成 `YYYY-MM-DD｜核心内容总结`。按 Codex 的会话活跃时间从新到旧扫描，遇到首个全合规批次就停止；标题日期单独按有效对话时间计算。

> **免责声明。** 只要一个批次中存在不合规标题，就会重命名该批全部会话，且没有内置回滚功能。使用前请先阅读 [SKILL.md](SKILL.md)。

## 它能做什么

| 能力 | 行为 |
| --- | --- |
| 语义化标题 | 根据完整会话的目标演进识别核心主题，再用实际结果补充。 |
| 最后对话日期 | 按系统当前时区，在每个标题前加入对应会话最后一次有效对话的日期。 |
| 手动增量执行 | 每批检查 20 条；发现任一不合规标题就重命名整批，首个全合规批次立即停止。 |
| 按会话选择语言 | 默认让每个标题跟随对应会话的主要用户语言。 |
| 显式指定语言 | `language=<language>` 可强制所有标题和用户可见输出使用同一种语言。 |
| Token 控制 | 运行环境支持模型选择时，优先使用低消耗模型，并只读取精简的会话上下文。 |
| 范围保护 | 排除 ChatGPT 对话和子代理会话。 |
| 不创建自动化 | 只有你明确调用 Skill 时才会执行。 |

## 命名与语言规则

标题格式：

```text
YYYY-MM-DD｜核心内容总结
```

日期取自最后一条有效用户消息或助手回复，执行过程中的进度播报不会改变日期。如果找不到有效的对话时间，则回退到创建日期。

未指定语言时：

- 每个标题使用对应会话自己的主要用户语言；
- 进度信息和最终报告使用当前触发 Skill 的对话语言；
- 如果会话语言不明确，则依次回退到当前标题语言、触发会话语言。

显式指定语言时：

```text
language=English
language=zh-CN
language=ja
```

指定语言会同时作用于所有新标题和所有用户可见输出。项目名、产品名、代码标识符和通用技术术语会在合适时保留原文。

## 环境要求

- OpenAI Codex，并且可以使用本地会话管理工具。
- 本地存在 `~/.codex/state_5.sqlite` 会话目录。
- Node.js 20 或更高版本。读取压缩后的会话记录需要 Node.js 22.15+ / 23.8+；更早的版本需要 `PATH` 中有 `zstd` 命令。
- `sqlite3` 已加入 `PATH`。
- 已在 macOS 上测试。

## 告诉 Codex 安装

直接告诉 Codex：

```text
请从 https://github.com/RuntianLee/codex-session-renamer 仓库根目录安装 codex-session-renamer Skill。
```

Codex 会使用内置的 Skill Installer，把 Skill 安装到 `$CODEX_HOME/skills`。安装完成后，下一轮对话即可使用。

## 使用方法

### 自动判断语言

```text
使用 $codex-session-renamer 修复近期 Codex 根会话标题。
```

### 强制使用同一种语言

```text
使用 $codex-session-renamer language=English 修复近期 Codex 根会话标题。
```

可将 `English` 换成语言名称或 BCP-47 标签，例如 `zh-CN`、`ja`。

> **重要：** 如果某批存在一个不合规标题，该批所有会话都会被重新总结和重命名。该 Skill 不提供定时模式、dry-run 或自动标题备份。

## 工作原理

1. 按 Codex 的 `recency_at_ms` 倒序排列根会话；每个标题的日期单独按该会话的有效对话时间计算。
2. 用 SQLite 只读模式查询当前批次，最多 20 个会话；以会话索引中时间最新的标题校验，返回 `batchCompliant` 和 `noncompliantCount`。
3. 如果返回的标题全部合规，立即停止。
4. 如果存在任一不合规标题，保存该批 ID 和下一批 offset，按这些固定 ID 读取上下文并重命名整批。
5. 对归档任务临时解除归档，重命名后恢复原状态；写入失败时也恢复归档状态。
6. 按同一批 ID 复查实际标题和归档状态；未持久化的写入重试一次，仍失败则报告并停止。
7. 修复批次验证通过后，按原先保存的 offset 继续；遇到下一批原本就全合规的标题或到达末尾时停止。

## `agents/` 和 `scripts/` 是做什么的

### `agents/`

这个文件夹里只有 `openai.yaml`，负责告诉 Codex 如何展示这个 Skill：

- 显示名称；
- 简短说明；
- 启动时显示的示例提示词。

它用于改善 Codex 中的使用体验，不负责扫描或重命名会话。

### `scripts/`

这个文件夹存放检查标题并为 Codex 准备会话信息的辅助脚本。

简单来说，脚本会：

1. 从 Codex 本地会话列表中找出普通根会话；
2. 跳过 ChatGPT 对话和子代理会话；
3. 使用 `session_index.jsonl` 中时间最新的名称修正数据库里的旧标题，再打开当前批次的本地会话，只保留最后有效对话日期、当前标题、从会话全过程分层抽取的最多四条用户要求，以及最后一条非进度类结果；
4. 去掉附带的 Skill 原文、代码块和页面标记等无关内容；
5. 支持轻量 `--check-only` 检查，不输出会话上下文，并与完整模式使用同一套日期计算方法。

脚本只读取本地文件。它不会自己决定标题、修改数据库或执行重命名。真正的标题写入由 Codex 官方会话工具完成。

采集器会拒绝未知参数和非法数值。`--limit` 接受 1–20，`--offset` 接受非负整数。读取或复查已选定批次时，用 `--ids id1,id2,...` 固定身份，保持传入顺序，并要求所有 ID 都对应现存根会话；它不能与位置分页参数混用。两种选择方式均可加 `--check-only`。历史字符串消息内容可以读取，无关或不完整 JSON 记录会跳过。Codex 会把较旧的会话记录压缩为 `<rollout_path>.zst`，此时采集器改读压缩文件；未压缩的原文件始终优先。

运行测试：`node --test tests/`。

## 安全与隐私

| 范围 | 保证 |
| --- | --- |
| 会话内容 | 只在本地读取，用于提取精简的命名上下文。 |
| 数据库 | 只查询会话元数据，不直接向 SQLite 写入标题。 |
| 重命名 | 使用 Codex 官方会话工具。 |
| 归档任务 | 重命名后恢复原来的归档状态。 |
| 排除范围 | 永不选择 ChatGPT 对话和子代理会话。 |
| 自动化 | 永不创建或更新定时自动化。 |
| 删除操作 | 永不删除会话、消息、记忆或项目文件。 |

## 已知限制

- 标题质量取决于每个会话中可用的有效上下文。
- 收集脚本依赖 Codex 当前的本地文件结构。
- 没有内置标题历史或自动回滚。
- 只重命名保存在本机的会话。Codex 的会话存在本地，在一台电脑上改名后，另一台电脑上它自己的会话不会跟着变；需要在每台电脑上分别运行。手机等设备如果是通过 [connected host](https://openai.com/index/work-with-codex-from-anywhere/) 远程查看本机会话，读取的就是本机数据，刷新后能看到新标题。
- 在网页、手机和桌面之间同步的 ChatGPT Work 对话与 Codex 历史是分开的（[OpenAI 文档](https://learn.chatgpt.com/docs/projects)），本 Skill 不会重命名它们。
